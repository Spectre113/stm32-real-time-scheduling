# Демонстрация планировщиков реального времени на STM32F767

[English version](README.md)

Проект STM32CubeIDE для исследования двух кооперативных подходов к планированию на `STM32F767ZITx`:

- **Superloop** - фиксированный невытесняющий порядок выполнения.
- **Chunked EDF** - синтетическая работа делится на кооперативные части, а после каждой части снова выбирается задача с наиболее ранним deadline.

Прошивка запускает периодические синтетические задачи и задачи физических датчиков, измеряет временные характеристики и выводит отчёты и CSV-строки через UART. Это экспериментальная платформа для воспроизводимых измерений, а не готовый промышленный планировщик.

## Что потребуется

- Плата `NUCLEO-F767ZI` со встроенным ST-LINK Virtual COM Port.
- USB-кабель с передачей данных.
- [STM32CubeIDE](https://www.st.com/en/development-tools/stm32cubeide.html) с STM32Cube FW F7.
- UART-терминал: [PuTTY](https://www.putty.org/) или Tera Term.

HC-SR04 и DHT11 необязательны. В текущей ручной конфигурации они включены, поэтому при отсутствии датчика установите соответствующий `ENABLE_REAL_TAU*` в `0`.

## Быстрый запуск

1. Клонируйте репозиторий или распакуйте архив.
2. В STM32CubeIDE выберите `File -> Import... -> General -> Existing Projects into Workspace`, укажите корень репозитория и завершите импорт.
3. Подключите плату к USB-разъёму ST-LINK и соберите проект через `Project -> Build All`.
4. Откройте ST-LINK Virtual COM Port в терминале до запуска прошивки: `115200`, `8N1`, без parity и flow control.
5. Нажмите `Run` или `Debug`. STM32CubeIDE прошьёт микроконтроллер и запустит программу.

Если COM-порт не появился, переподключите плату и обновите драйвер ST-LINK. В проекте используется `USART3` (`PD8` - TX, `PD9` - RX); см. [`demonstration.ioc`](demonstration.ioc).

## Настройка и запуск эксперимента

Все ручные переключатели собраны в начале [`Core/Src/main.c`](Core/Src/main.c). После изменения требуется собрать и заново прошить проект. Текущие значения по умолчанию: `U50`, Superloop, интегрированный профиль, окно 60 секунд и оба физических датчика включены.

```c
#define WORKLOAD_SCENARIO WORKLOAD_SCENARIO_U50
#define SCHED_ALGO SCHED_ALGO_SUPERLOOP
#define EXPERIMENT_MODE EXPERIMENT_INTEGRATED
```

Чтобы выбрать нагрузку, окно измерения, алгоритм, число задач или режим профилирования, используйте [справочник по конфигурации](docs/configuration.ru.md). В нём также описаны CSV-вывод и назначение всех макросов.

Пути выполнения для двух алгоритмов принципиально различаются:

- В Superloop HC-SR04 и DHT11 работают через блокирующие baseline-транзакции.
- В Chunked EDF ожидание датчиков представлено как состояние not runnable, поэтому планировщик может выполнять другую готовую работу. HC-SR04 получает фронты ECHO через EXTI, а DHT11 имеет видимое планировщику 30 ms ожидание start-low.

В [руководстве по датчикам](docs/sensors.ru.md) описаны обе state machine, используемые пины и короткие аппаратные smoke-тесты.

UART-вывод появляется только после окончания окна профилирования. Сохраните CSV-строку для анализа. Если терминал был открыт слишком поздно, перезапустите плату: результат мог уже быть выведен.

## Автоматический сбор серии экспериментов

[`tools/experiment_runner/`](tools/experiment_runner/) умеет собрать, прошить, прочитать UART и объединить CSV-строки для целой матрицы экспериментов. Скрипт не изменяет ручные переключатели в `main.c`, сохраняет отдельные логи и `results/<timestamp>/summary.csv`, а результаты не попадают в Git.

Настройка, матрицы и команды описаны в [руководстве по автоматизации](tools/experiment_runner/README.ru.md).
